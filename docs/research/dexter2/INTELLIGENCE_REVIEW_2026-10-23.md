## Correctness gaps to close before making the system feel smarter

1. **The displayed “Independent accuracy and pace” is not the knowledge stream.** `LearningInsightsService::forUser` uses `SkillEvidenceBuilder` for BKT/`nextFocus`, but independently increments `mastery`, `skills` and `history` for every non-assisted served question. A blank is counted wrong, and a repeat is counted again. The analytics card says “Independent accuracy” and “% ... on your own”; its timed suggestion can be raised by repeats. This may be a legitimate *mock scoring* convention, but it is the wrong label and denominator for *first-attempt learning*. Keep authoritative exam scores as scored, and derive learning accuracy/stages/timed suggestions from a consistent independent answered-only stream, with omissions and repeats displayed separately. Add tests for blank, same-day repeats, helped-first, offline repeats and cross-source events.
2. **The 50-attempt insight window can lose the first exposure.** `LearningInsightsService` loads only the latest 50 `ExamAttempt` rows and 500 offline rows before the evidence builder. When an older first answer drops out, a repeat of the same ID in the window can be mistaken for a fresh first answer. `ExposureHistory` already searches all history for selection, but is not a full chronological response record. Design a bounded, owner-scoped first-answer ledger or an equivalent reliable query before using `nextFocus` as a durable skill signal. Test >50 attempts and offline/online order without modifying existing history.
3. **The Rescue gate is not ready to open.** `config/dexter_rescue.php` has `validated_question_ids=[]`, and the editorial pilot has no recorded human decisions. `RescueController` accepts a client-supplied question ID and chosen option without confirming a server-recorded graded Study response. Its lock protects an active Strict Mock, but the endpoint must authenticate the relevant served/graded attempt before diagnosis or a new question. This is an activation prerequisite, not a reason to enable Rescue now. Also verify that the fresh follow-up differs in *stem family*, not just exact stem and ID.
4. **Old “Dexter evaluation” wording overstates a narrow check.** `DexterEvaluationService::evaluate` returns `aiEvaluation: Basic verification passed` and `confidence: 0.85` for a generic active item; only one earnings/day phrase receives a narrow calculation check. `ExamController::revealAnswer` includes this object in the Reveal response. This is not an independent answer audit. Remove the invented confidence and replace the blanket success message with an honest “not checked by this validator” state, preserving the actual conflict flag only where a supported deterministic check ran. Regression-test the response contract before changing it.
5. **The graph is coarse for GT's Subprofessional math path.** `NUM-FRAC-DEC` merges meaning/equivalence/operations/decimals, while `NUM-WP-RATE` merges speed, work and unit price. A learner who fears fractions needs diagnosis at the actual prerequisite level. First audit and tag approved items for fraction meaning, equivalence, operations, percent base, ratio, algebra translation and rate units; version the graph only when the bank can supply distinct approved teaching and unseen transfer items for each node. Do not pretend a missing skill has adequate coverage.

### Founder-first private study path

Start with short unseen Subprofessional MCQ diagnostics for arithmetic, fraction meaning/equivalence, percent base, ratio and word-to-equation translation. A low score on a downstream skill triggers a few prerequisite questions, written worked steps and another *different* approved item. Distinguish untimed method learning, first independent accuracy, delayed retention and timed mixed performance. Use the existing account/history and Study/Strict modes. Do not create a privileged answer key or contaminate Strict. If a prerequisite has no adequate approved items, report the gap instead of improvising a teaching claim.

## Decisions and boundaries

- Keep two modes. Study optimizes learning; Strict measures performance under a representative **Civio** blueprint and reports repeats separately. Neither yields an official CSC pass prediction.
- Keep BKT fixed and internal while uncalibrated. The most useful new “intelligence” is trustworthy event accounting, approved misconception metadata, prerequisites and fresh transfer.
- Do not activate Rescue or generative inference from this review. No new UI system, payment, provider, protected database operation, bank import or deployment is proposed.
- This review did not run PHP application tests or inspect live learner records. It inspected repository code, test cases and committed snapshot metadata. Existing issue priorities may be superseded by later commits; recheck `main` before each work package.
