## 2. Ranked findings

Ranking = student impact × urgency ÷ effort. F1 to F3 are integrity or honesty defects. They should be fixed before any public deploy.

### F1. Any visitor can get the full answer key for any question, including locked Strict Mock items and drafts — **Critical**
- **What:** `POST /exams/attempts` (public route, `routes/web.php:62`) accepts any `question_ids` when `exam_session_id` is omitted. `ExamGradingService::grade` returns `answer_keys` (`correct_option` + `explanation`) for every ID, and the controller never consults `StrictMockLock`.
  - Repro (test P1): open a Strict Mock and confirm that Reveal returns 423. Then POST `/exams/attempts` with the same item IDs, any answers and no session ID. The result is **200, with all 9 keys and explanations**.
  - Guests must "answer" every item, but any filler value counts as an answer. Signed-in users need 50%.
- **Why:** it defeats Strict Mock, lets anyone scrape the whole bank with keys in a few requests, and exposes unapproved drafts. Each fake attempt is also stored and feeds the analytics (see F3).
- **Doc drift:** the `StrictMockLock` docblock says keys are withheld from "drill payloads, scorecards of older attempts and grading of any other attempt". The code enforces only Reveal, Expound and PDF export.
- **Source/date:** code at `4d4ed95`, 17 Oct 2026. Evidence **A** (test).
- **Civio covers it?** No. No test covers it.
- **Urgency:** before deploy.
- **Decision (Astra):**
  - Free-form attempts should accept only active items, never return keys for locked items, and probably require a server session for anything that counts as a mock.
  - Add a regression test.

### F2. Strict Mock score and time are not enforced by the server — **High**
- **What, three independent gaps:**
  1. **No server deadline.** Submitting a Strict session 2h50m after its limit is accepted. The lock expires at limit + 10 min, so the learner can wait, Reveal every key, then submit for 100% recorded as `mode=strict` (test P3).
  2. **Subset submit.** `SubmitExamAttemptAction` only checks `array_diff(submitted, served)`, so submitting 2 of 9 served items scores 2/2 = 100% as a Strict attempt (test P2).
  3. **Client clock.** `use-exam-timer.ts` subtracts 1 per `setInterval` tick, and resume (`use-exam-state.ts:426`) restores the saved `timeLeft` without subtracting the time that has passed. Closing the tab freezes the clock, and resume is allowed for up to 30 days.
     - On phones, Chrome checks chained timers in hidden pages only **once per minute** after 5 minutes ([Chrome timer throttling](https://developer.chrome.com/blog/timer-throttling-in-chrome-88)). So switching apps makes the Strict clock run about 60× slow. That is an accuracy bug as well as a cheating vector.
- **Why:** Strict Mock is the only thing the roadmap allows to feed "Readiness" (§0.2). Competitors advertise a "server-truth timer" (CSEPass, cseexamreview.com).
- **Source/date:** code at `4d4ed95`, plus Chrome docs. Evidence **A** for 1 and 2, **B** for 3.
- **Civio covers it?** No.
- **Urgency:** before Readiness or any Strict-based meter ships.
- **Decision:**
  - Store `expires_at` on `exam_sessions`.
  - Compute remaining time as `expires_at − now` on the client.
  - Reject or flag late Strict submits.
  - Require the full served set, with unsent items counted as blank.

### F3. The "AI Readiness Predictor" shows an invented pass percentage — **High (honesty)**
- **What:**
  - The dashboard bento card is titled "AI Readiness Predictor" and shows `${prob}%`, green at ≥80 (`ai-readiness-bento-card.tsx:145,199`).
  - The number is `round(mockAvg × 0.9)`, +5 if "improving" or −8 if "declining" (`DeterministicAnalysisService.php` around line 509). It is not AI, not calibrated, and not a probability.
  - "Mock" means any attempt whose **client-sent** `metadata.track` is not "Drill". That includes Study mode with Reveal, subset submits (F2) and free-form attempts (F1).
- **Why:** this conflicts with `docs/ADAPTIVE_LEARNING.md` and `ENGINES.md`, which say "Not done, and not claimed: pass probabilities". It breaks the "never invent pass rates" rule and can mislead students about exam readiness. The small-print disclaimers do not offset a big green percentage.
- **Source/date:** code at `4d4ed95`. Evidence **A** (read; formula is unambiguous).
- **Civio covers it?** No. The docs claim the opposite.
- **Urgency:** before deploy.
- **Decision (GT + Astra):**
  - Rename and reshape the card, e.g. "Latest full Strict Mock: 74% (80 needed)".
  - Count only server-session Strict attempts.
  - Drop "AI" and "Predictor".

### F6. Reveal and Expound serve drafts, and the bank can be scraped — **Medium**
- **What:**
  - `revealAnswer` and `expoundAnswer` validate only `exists:questions,id`, with no `status=active` check. Repro (test P4): a draft item's key and explanation come back with 200.
  - In production, `global-views` allows 120 requests/min per IP, so a 1,900-item bank is downloadable in about 16 minutes from one IP.
  - The Strict lock is per account or browser session, so a second browser bypasses it.
- **Why:** drafts that Chief of Staff (CoS) has not approved can be wrong, and that leaks unvetted keys. Scraping is a business risk, since competitors sell banks of 1,900+ items.
- **Source/date:** code. Evidence **A**.
- **Civio covers it?** No.
- **Urgency:** before deploy.
- **Decision:** filter to active items only. Consider tighter per-route limits and requiring a session-served or drill-served item before Reveal.

### F7. The bank is skewed: thin English reading and paragraph skills, rote-heavy GI — **Medium-High (content)**
- **What:** approved Civio items by archetype (repo JSON; baseline 550 not broken down):
  - English: reading comprehension 4 (+17 vocabulary-in-context), paragraph organization 3, and no item tagged sentence structure. Official scope lists all three.
  - GI: `GI-DEADLINE-NUMBER` 51 and `GI-TERM-MATCH` 38, against `GI-SCENARIO-APPLY` 3. That is memorising numbers rather than applying R.A. 6713.
  - Numerical: `NUM-WP-PCT-CHANGE` has 78 items, about 26% of Civio's numerical items.
- **Why:** mocks inherit the skew, so practice scores misrepresent weak areas. The 100-item English draft (batch 002) is the fastest fix, if it covers reading and paragraph organization.
- **Source/date:** `docs/batches/*.json`, `docs/research/*.json`, and the `COVERAGE_GAP_MAP.md` scope, 17 Oct 2026. Evidence **A** (counted).
- **Civio covers it?** The gap map flags reading and paragraph organization. It does not flag the GI rote skew or the percent-change overweight.
- **Urgency:** next content rounds.
- **Decision (GT/CoS):** set per-archetype caps or targets in the ChatGPT prompts, and audit the baseline 550 by archetype.

### F8. Adaptive learning: build the mistakes queue and FSRS; defer BKT and IRT — **High impact, moderate effort**
- **What:** I agree with `LEARNING_DELIVERY_RECOMMENDATION.md` (Review Mistakes queue first, then FSRS), with three adjustments:
  1. **FSRS due dates are low-stakes.** Correctness must be graded on the server, but a due date is not a security asset. Store the review log server-side and let `ts-fsrs` compute the next due date. ts-fsrs is MIT-licensed, v5.4.2, last pushed 16 Oct 2026, and already a dependency. Clamp due dates server-side rather than porting FSRS to PHP. The only PHP option found, `open-spaced-repetition/fsrs-rs-php`, has 8 stars (MIT), too thin to depend on.
  2. **IRT and BKT are not practical yet.** Civio has no production users. Calibrating IRT items needs hundreds of responses per item (common psychometric guidance, not a Civio measurement). pyBKT (MIT, active) needs a skill tag on every item and a training set. Instead, ship classical item analysis first: % correct, distractor pick rates and point-biserial per item, from real attempts. That works with dozens of responses and flags bad keys, which serves the bank's quality goal directly.
  3. **The existing distractor codes are a ready-made misconception model.** Every approved item tags each wrong option with a spec code (e.g. `FIL-SPOKEN-FORM`, `RC-NOT-IN-TEXT`). "You keep choosing RC-NOT-IN-TEXT" is more useful and more honest than a mastery %.
- **Source/date:** [ts-fsrs README](https://github.com/open-spaced-repetition/ts-fsrs) and GitHub API metadata, 17 Oct 2026. Evidence **B**.
- **Civio covers it?** Scheduler only (§0).
- **Urgency:** next feature.
- **Decision (Astra):** whether due dates may be client-computed and clamped. Add item-analysis tables to the Review Mistakes slice.

### F9. Cheap automated QA for Filipino grammar and maths keys — **Medium impact, low effort**
- **What:**
  - LanguageTool (LGPL-2.1, very active) ships a Tagalog module whose `grammar.xml` has 44 rules, including **`NG_NANG`, `D_AND_R` (din/rin, daw/raw) and `LIGATURE_USAGE`**. That is exactly the error class CoS keeps fixing by hand (round 03 → FIL-SPOKEN-FORM).
  - Run it as a local server during `qa.py` only, so there is no runtime or bundle cost, and the LGPL code stays a separate process. Treat hits as warnings for a human, since the module is small: dictionary about 51 KB.
  - For Numerical, a SymPy recompute harness (BSD licence) in `qa.py` can re-derive keys for structured archetypes (percent change, ratio, average, rate). This extends what the `RevealTutor` solvers already do at runtime.
- **Not recommended now:** calamanCy (MIT, 75 stars, v0.2.3 Jul 2026, spaCy-based). It is good for Tagalog POS/NER research, but it does not check the ng/nang class, and it adds a heavy Python model for little gain.
- **Source/date:** [LanguageTool tl rules](https://github.com/languagetool-org/languagetool/tree/master/languagetool-language-modules/tl), [calamanCy](https://github.com/ljvmiranda921/calamanCy), checked 17 Oct 2026. Evidence **B**.
- **Civio covers it?** `qa.py` has regex checks only (nakaka-, kanya/kanyang, order keys).
- **Urgency:** before the next Filipino batch.
- **Decision:** who owns `qa.py` changes (the audit agent, not Astra).

## Appendix A: integrity probe (throwaway; run in an isolated clone, never commit)

Place it at `tests/Feature/SentinelProbe/ProbeTest.php` in a scratch clone and run `php artisan test tests/Feature/SentinelProbe`. It reuses `seedMockBank()` from `tests/Feature/User/ExamSessionTest.php`. Results on `4d4ed95`:

```
P1 status=200 keys=9 first={"id":8,"correct_option":2,"explanation":"Because C."}   # keys via /exams/attempts during open Strict
P2 served=9 submitted=2 status=200 score=100 total=2 mode=strict                    # subset submit
P3 status=200 score=100 mode=strict                                                 # late submit after keys unlocked
P4 status=200 key=3 expl="DRAFT EXPLANATION"                                        # draft key via Reveal
```

```php
<?php
use App\Models\ExamAttempt; use App\Models\Question; use App\Models\User;
require_once __DIR__.'/../User/ExamSessionTest.php';

test('P1', function () {
    seedMockBank(3); $this->actingAs(User::factory()->create());
    $s = $this->postJson(route('exams.sessions.store'), ['track' => 'Subprofessional', 'mode' => 'strict'])->assertOk();
    $ids = collect($s->json('questions'))->pluck('id')->all();
    $this->postJson(route('exams.reveal'), ['question_id' => $ids[0]])->assertStatus(423);
    $r = $this->postJson(route('exams.attempts.store'), ['question_ids' => $ids,
        'answers' => collect($ids)->mapWithKeys(fn ($id) => [(string) $id => 0])->all(), 'metadata' => ['track' => 'Subprofessional']]);
    expect(count((array) $r->json('answer_keys')))->toBeGreaterThan(0); // passes today = bug
});
test('P2', function () {
    seedMockBank(3); $this->actingAs(User::factory()->create());
```
